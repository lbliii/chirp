**Shapes — `shapecheck` soundness and bounded-compiler hardening.** Several `@shape` defects that produced false contract failures or silently degraded runtime behavior are fixed. **`shapecheck` (false-positive / attribution):** reading a `nested()` relationship root (e.g. `{% for card in board.cards %}` over `cards = nested(Card, ...)`) is no longer flagged as an under-fetch — nested fields are recognized as Shape-provided; a block's reads are now its **own** reads (a nested child block's reads are subtracted from the parent's conservative-superset dependency set), so a read in a child block bound to a different Shape no longer false-fires against the parent, and a genuine under-fetch names the innermost block where the read lives instead of the bound ancestor; context-noise/global/local names are now matched as bare context keys, so a Shape column named `form`/`error` is no longer silently uncheckable; the `| default(none)` removal hint is only emitted when the read actually carries that guard; and an un-analyzable route (source unavailable) now emits an INFO instead of silently dropping its bindings. `Shape.validate(cls)`'s nested/scope checks are now actually invoked by `shapecheck` at `app.check()` startup (previously the validator existed but no production path called it). **Bounded nested compiler (silent degradation / crashes):** a child SQL's trailing `ORDER BY` is preserved (re-attached after the `IN`-list) and a per-parent `LIMIT` is compiled into a window-function top-N (`ROW_NUMBER() OVER (PARTITION BY {on} ORDER BY ...)`) instead of being silently dropped — "top 5 recent comments per card" no longer becomes "all comments, arbitrary order"; deterministically-inexpressible cases (`LIMIT` with no `ORDER BY`, `OFFSET`, or a `LIMIT` on a child that also has nested grandchildren) fail loud at startup; parent keys for a level's `IN`-list are chunked to a driver-safe variable limit, so a level with tens of thousands of distinct parent keys no longer hard-crashes with SQLite's "too many SQL variables" — the query count stays independent of child row count (the docs' "independent of N" claim is corrected to "independent of child row count; parent keys are chunked"). **Tenant scope (security):** scoped Shapes whose outer `FROM` is a derived table or subquery (`SELECT ... FROM (SELECT ... WHERE ...) x`) — previously injectable-looking but producing invalid/unscoped SQL that passed `app.check()` and crashed (or under-scoped) at runtime — now fail loud at startup; the scope-predicate-already-present detection no longer matches only the literal `col = :scope`, so an author-written non-canonical scope predicate (`col = :tenant`, `col IN (...)`) is rejected with a clear `ShapeError` rather than silently double-injected; and the placeholder binder is now a single quoted-string- and `::`-cast-aware scanner shared by both the bind and discovery paths, so a colon inside a string literal (`'12:30:00'`) is no longer misparsed as a bind placeholder.

  **Note** — `app.override_contract_severity("shapecheck", ...)` operates on the **whole category**: softening it to quiet over-fetch also demotes registry-drift, under-fetch, and un-injectable-scope from ERROR. The Shapes guide's severity-lever example is corrected to call this out. (#166/#167/#169/#173)

  **Round-2 hardening** — tenant scope-column matching is now word-boundary anchored, so a scope column like `community_id` no longer substring-false-matches a longer column (e.g. `community_id_legacy`) and cannot leak a mis-targeted predicate; the Shape SQL scanner is comment-aware (`:name`-shaped tokens, scope columns, and clause keywords inside `--`/`/* */` comments or string literals are not treated as analyzable SQL); and a nested child's non-join `WHERE` filter predicates (e.g. `AND deleted = 0`) are preserved in the batched `IN`-list/top-N form rather than dropped.

  **Round-3/4 hardening** — a per-parent-LIMIT window child whose outer `ORDER BY` sorts on a column it does not project (the canonical `ORDER BY created_at DESC LIMIT N` where `created_at` is not SELECTed) no longer crashes with "no such column" — the outer query orders on the projected `{on}, __chirp_rn` (within-parent order is preserved by the inner `ROW_NUMBER()` ranking); the reserved `__chirp_` placeholder prefix is now **fail-loud enforced** at `@shape` decoration, so an author whose declared SQL writes a `:__chirp_k0`/`:__chirp_rn` placeholder (which would silently bind to a compiler-generated value at fetch time and return wrong/empty rows) is rejected with a clear `ShapeError` instead of passing `Shape.validate` and mis-binding at runtime; a scoped nested child carrying an author-written predicate on the scope column reaches the same "ambiguous scope ownership" fail-loud as the parent path (the child residual is re-parenthesized at runtime, so the depth-0 conflict check would otherwise miss it); and the scope-injectability gate is comment-aware — a scoped shape whose SQL merely mentions `WITH`/`UNION`/`INTERSECT`/`EXCEPT` inside a `--`/`/* */` comment is no longer false-rejected as a compound/opaque query, and a depth-0 `WHERE` that begins with a comment before its first predicate (`WHERE /* c */ a = :a`) now injects valid, executable scoped SQL instead of a malformed `WHERE AND …`. Two more `shapecheck` soundness defects are fixed: the under-fetch de-duplication key now carries the **bound Shape identity**, so two genuinely distinct bindings that share a template variable name and resolve to the same attributed block (a bound parent on one Shape and a bound nested child on another, each missing the same field name) report **both** real under-fetch ERRORs instead of silently collapsing into one; and over-fetch is now computed against the **union** of reads across every binding of a Shape, so a column the parent block SELECTs that is read only by a nested child block bound to the same Shape is no longer mis-flagged as a spurious over-fetch WARNING on the parent.
