**htmx provisioning contract (`htmx_provisioning`).** `app.check()` now ERRORs when a page emits `hx-*`/`sse-*` attributes but htmx is not provisioned — those attributes are inert and the UI silently does nothing with no console error. The rule recognizes both provisioning modes and only fires when neither is present: `AppConfig(htmx=True)` (Chirp's `HtmxInject` injects the runtime page-wide), or an explicit htmx `<script src="…htmx…">` reachable from the page's template/layout/extends chain (including the framework shell `chirp/layouts/shell.html` that chirp-ui apps extend). The check is evaluated **per page**: only full-page renders (`Template`/`Page`/`Suspense`/`Stream` returns and filesystem page leaves) must self-provision, and a script in one page never suppresses an unprovisioned sibling page. Fragment-only templates (returned solely via `Fragment`/`ValidationError`/`OOB`) swap into an already-loaded host page, so the host owns provisioning and the fragment is not flagged on its own. Framework-shipped templates (`chirp/`, `chirpui/`, `chirp_docs/`) are not the app developer's responsibility, so their usage is skipped. Self-host htmx under a name the `src`-contains-`htmx` heuristic cannot see? Set `AppConfig(htmx=True)` as the explicit opt-in.
